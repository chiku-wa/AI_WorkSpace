# メンバー予定のHTML出力プロンプト

以下の要件を満たす、単一ファイルで動作するHTMLダッシュボードを作成してください。

## 目的

月間カレンダーの日付セルに記載されたチームメンバーの休暇予定を解析し、システムごとの稼働担当者数を午前・午後に分けて判定する。

担当者不足が発生する日を、カレンダー上で分かりやすく可視化すること。

HTML・CSS・JavaScriptを1つのHTMLファイルにまとめ、ブラウザで直接開くだけで動作するようにする。サーバー、外部API、外部ライブラリは使用しない。

## 入力データの前提

入力データは、月間カレンダー形式で記載されている。

各日付セルには、次のように日付・氏名・予定が複数行で記載される。

```text
14
佐藤　一日年休
鈴木　AM年休
```

この例は、14日について次の予定を表す。

- 佐藤：一日年休
- 鈴木：AM年休
- 予定の記載がない担当者：通常稼働

氏名と予定の間には、タブ、全角スペース、半角スペースのいずれかが入る場合がある。

## 月間カレンダーの入力例

Markdown表では、次のように入力される。

```markdown
対象年月：2026年8月

| 日 | 月 | 火 | 水 | 木 | 金 | 土 |
|---|---|---|---|---|---|---|
|  |  |  |  | 13<br>鈴木　一日年休<br>田中　PM年休 | 14<br>佐藤　一日年休<br>鈴木　AM年休 | 15 |
| 16 | 17<br>佐藤　一日年休<br>鈴木　一日年休<br>田中　一日年休<br>伊藤　PM年休 | 18 | 19 | 20 | 21 | 22 |
```

以下の記法をすべて日付セル内の改行として扱うこと。

- 実際の改行
- `<br>`
- `<br/>`
- `<br />`

日付セルの1行目を日付、それ以降を予定として解析する。

## 担当者マスター

カレンダーだけでは、担当者がどのシステムを担当しているか分からないため、システムと担当者の対応を別のMarkdown表で管理する。

```markdown
| システム | 担当者 |
|---|---|
| 販売管理 | 佐藤 |
| 販売管理 | 鈴木 |
| 販売管理 | 田中 |
| 会計 | 高橋 |
| 会計 | 伊藤 |
```

同じ担当者が複数システムを担当している場合は、システムごとに1行ずつ記載する。

```markdown
| システム | 担当者 |
|---|---|
| 販売管理 | 佐藤 |
| 会計 | 佐藤 |
```

担当者マスターに登録された担当者を、そのシステムの通常体制として扱う。

## 休暇予定の判定

以下の予定表記に対応すること。

| 予定表記 | 午前 | 午後 |
|---|---:|---:|
| 一日年休 | 休み | 休み |
| 一日休暇 | 休み | 休み |
| 一日休み | 休み | 休み |
| 終日年休 | 休み | 休み |
| 終日休暇 | 休み | 休み |
| 終日休み | 休み | 休み |
| AM年休 | 休み | 稼働 |
| AM休 | 休み | 稼働 |
| 午前年休 | 休み | 稼働 |
| 午前休 | 休み | 稼働 |
| PM年休 | 稼働 | 休み |
| PM休 | 稼働 | 休み |
| 午後年休 | 稼働 | 休み |
| 午後休 | 稼働 | 休み |

次の場合は、午前・午後とも通常稼働として扱う。

- カレンダーに氏名が記載されていない
- 予定が空欄
- `稼働`
- `出勤`
- `通常勤務`

未対応の予定が入力された場合は、無視せず次の情報をエラーとして表示する。

- 日付
- 氏名
- 未対応の予定
- 対応可能な予定表記

## 氏名の照合

カレンダーに記載された氏名を、担当者マスターの氏名と照合する。

照合前に以下を正規化すること。

- 氏名の前後の空白を削除
- 連続する空白を1個に統一
- 全角スペースと半角スペースの違いを吸収
- 氏名と予定の間のタブを空白として扱う

担当者マスターに存在しない氏名がカレンダーへ記載されている場合は、次のような警告を表示する。

```text
8月14日の予定にある「山本」は、担当者マスターに登録されていません。
```

同じ日付に同じ担当者の予定が複数記載されている場合も、重複エラーとして表示する。

## 判定ルール

システムごとに、午前・午後それぞれの稼働人数を集計する。

- 稼働0名：警告
- 稼働1名：要注意
- 稼働2名以上：問題なし

担当者マスターに3名登録されているシステムで、2名が休みの場合は、残る1名を稼働担当者として要注意にする。

## 固定色

警告と要注意には固定色を使用し、ライトモードとダークモードで変化させない。

- 警告：赤 `#dc2626`
- 警告の文字：白 `#ffffff`
- 要注意：黄色 `#facc15`
- 要注意の文字：濃色 `#3b2f00`
- 問題なし：緑系

警告・要注意の色をテーマ変数と混合しないこと。

カレンダー、吹き出し、一覧、詳細画面のすべてで同じ色を使うこと。

## 画面構成

### 1. 月間カレンダー

画面冒頭に月間カレンダーを配置する。

- 入力された対象年月を表示する
- 日曜日から土曜日までの7列で表示する
- 各日付セルに警告件数と要注意件数を表示する
- 警告と要注意が両方ある場合は両方表示する
- 問題がない場合は「問題なし」と表示する
- 休暇予定がない日も、担当者全員が稼働しているものとして判定する
- 対象月以外の日付は表示しないか、薄く表示する
- 本日のセルには太いリングと「本日」ラベルを付ける
- 本日判定にはブラウザの現在日付を使用する

### 2. マウスオーバーによる詳細表示

日付セルへマウスを乗せると、クリック不要で吹き出しを表示する。

キーボードで日付セルにフォーカスした場合も、同じ吹き出しを表示する。

吹き出しには、システムごとに以下を表示する。

- 絵文字付きシステム名
- 通常体制の人数
- 通常の担当者全員
- 午前の稼働担当者
- 午前の休暇取得者
- 午前の判定
- 午後の稼働担当者
- 午後の休暇取得者
- 午後の判定
- 判定理由の文章

吹き出しは画面外にはみ出さないように、自動的に位置を調整する。

## 判定理由の文章

人数だけでなく、なぜ警告・要注意になったかを自然な文章で説明する。

### 要注意の例

```text
🛒 販売管理は通常3名体制（佐藤、山田、鈴木）です。山田（一日年休）と鈴木（AM年休）が休みのため、午前は佐藤のみの1名体制となり要注意です。
```

### 警告の例

```text
🛒 販売管理は通常3名体制（佐藤、山田、鈴木）です。佐藤（一日年休）、山田（一日年休）、鈴木（AM年休）が休みのため、午前の稼働担当者が0名となり警告です。
```

### 問題なしの例

```text
🛒 販売管理は通常3名体制（佐藤、山田、鈴木）です。鈴木（AM年休）が休みですが、午前は佐藤と山田の2名体制で問題ありません。
```

文章には必ず以下を含める。

- システム名
- 通常体制の人数
- 通常の担当者名
- 午前または午後
- 休暇取得者
- 各人の休暇区分
- 稼働する担当者
- 実際の稼働人数
- 判定結果

同じ日に午前と午後で状態が異なる場合は、それぞれ別に説明する。

## 警告・要注意一覧

カレンダーの下に、警告と要注意だけを日付順のリスト形式で表示する。

並び順は次のとおり。

1. 日付の昇順
2. 午前、午後の順
3. 警告、要注意の順
4. システム名の順

各行には以下を表示する。

- 日付と曜日
- 午前または午後
- 警告または要注意のバッジ
- 絵文字付きシステム名
- 通常体制
- 休暇取得者
- 残る担当者
- 判定理由の文章

一覧をクリックすると、その日の詳細ダイアログを開く。

## 詳細ダイアログ

詳細ダイアログには、システム別・午前午後別に以下を表示する。

- 絵文字付きシステム名
- 通常体制
- 通常の担当者
- 稼働人数
- 稼働担当者
- 休暇取得者
- 各人の休暇区分
- 警告・要注意・問題なしの判定
- 判定理由

## システム別の絵文字

システム名のキーワードから絵文字を自動割り当てする。

- 販売、受注、在庫、商品：🛒
- 会計、経理、財務、請求：💰
- 顧客、CRM、会員：👥
- 人事、勤怠、給与：🧑‍💼
- 物流、配送、倉庫：🚚
- 監視、運用、セキュリティ：🛡️
- 基幹、統合：🏢

該当しないシステムには、システム名から決定論的に以下のいずれかを割り当てる。

- 🖥️
- ⚙️
- 📦
- 🧩
- 🗂️

同じシステムには、画面内のすべての場所で同じ絵文字を使用する。

## 入力編集機能

「入力データを編集」ボタンを配置する。

ボタンを押すとダイアログを開き、次の2種類のデータを編集できるようにする。

- 担当者マスター
- 月間カレンダー

タブまたは見出しで、2つの入力欄を分ける。

「反映」ボタンを押したときに以下を実行する。

1. 担当者マスターを解析
2. 月間カレンダーを解析
3. 氏名を照合
4. 入力エラーを表示
5. システムごとの稼働人数を再集計
6. カレンダーと一覧を再描画

入力内容は`localStorage`へ保存し、ページを再読み込みしても維持する。

## デザイン

- 業務用ダッシュボードとして、見やすく落ち着いたデザインにする
- 月間カレンダーを画面の中心要素にする
- 過剰なサマリーカードを追加しない
- 警告・要注意は、色だけでなく文字でも区別する
- ライトモードとダークモードの両方に対応する
- 警告と要注意の固定色はモードによって変更しない
- 画面幅320px程度のスマートフォンでも表示が崩れないようにする
- PCでは十分な情報量を表示する
- スマートフォンでは文字や一覧を適切に折り返す
- 横スクロールや文字の重なりを極力発生させない

## アクセシビリティ

- 操作要素には`button`など適切なHTML要素を使用する
- 日付セルには、日付・警告件数・要注意件数が分かる`aria-label`を付ける
- マウスオーバーだけでなく、キーボードフォーカスでも吹き出しを表示する
- 色だけに依存せず、「警告」「要注意」「問題なし」の文字を表示する
- ダイアログには`dialog`要素を使用する
- HTMLへ挿入する入力値は必ずエスケープし、XSSを防止する

## 実装条件

- HTML・CSS・JavaScriptを1つのHTMLファイルにまとめる
- 外部ライブラリ、CDN、API、サーバー処理を使用しない
- JavaScriptでMarkdown形式の担当者マスターと月間カレンダーを解析する
- 日付セル内の複数行の予定を解析する
- 氏名と予定の区切りとして、タブ、全角スペース、半角スペースに対応する
- 予定が記載されていない担当者は通常稼働として扱う
- 午前と午後を別々に集計する
- JavaScriptの構文エラーがないことを確認する
- カレンダー、吹き出し、一覧、詳細ダイアログ、入力編集が実際に動作することを確認する
